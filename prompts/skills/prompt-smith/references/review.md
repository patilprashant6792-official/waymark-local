# Review and compression

## Anti-patterns

| Instead of | Write |
|---|---|
| "You are a world-class expert who…" paragraph | one-line role, or none |
| Repeated "remember to…" | one statement, right section |
| Stacked ALL-CAPS warnings | calm statement + reason |
| Telegraphic fragments ("chk usr, rtn err") | short complete clauses |
| Vague quality words ("good", "proper") | concrete criterion |
| Negative-only rule ("no bullets") | positive target ("write prose paragraphs") |
| Several near-identical examples | varied examples, marked illustrative |
| Change history ("previously we…") | current state only |

## Example

Before (~50 words):
> It is very important that you always make sure to check whether the user has provided an email address, and if they haven't provided one, you should politely ask them to provide it before continuing, because we really need it in order to send them the confirmation of their order.

After (~12 words):
> No email given → politely ask for it before continuing; it's needed for order confirmation.

Over-compressed (rejected — drops the reason and "politely", needs decoding):
> !email → ask
